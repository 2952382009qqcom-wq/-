## 入口与权限

- 普通用户和评委测试账号：`/`，登录接口 `/api/auth/login`。
- 管理员：`/admin`，登录接口 `/api/admin/login`。管理员账号不能在普通入口登录。
- 管理员列表与普通用户列表分开；所有管理接口继续在服务端验证角色。
- 管理员在管理页修改本人用户名和密码，必须验证当前密码。重启不会重置已修改的密码，也不会把同名普通用户提升为管理员。
- 新建测试账号为 `is_admin=False, is_approved=True, is_test_account=True`，隐藏试用额度、不限应用内调用次数，但不能访问管理接口。其他未批准用户保留原试用额度。
- 默认关闭自动测试账号初始化，不再创建公开固定密码的账号。显式初始化必须提供至少 12 位密码；已有账号的密码、模型和撤销状态不会被启动流程覆盖，同名普通账号或管理员不会被提权。
- 上游 `8a34ac6` 已新增 `is_test_account`、举报处理人及治理表。旧版本部署前必须备份并验证增量建表、补列流程，不能以“无需迁移”代替数据库检查；本次未对生产库执行任何操作。

### 三级内容治理

- 高危：拒绝发布或编辑，原内容保持不变。
- 中危：隐藏内容并进入人工审核队列，编辑不会重复生成待审记录。
- 低危：提示用户，仍允许公开发布。

帖子新建、编辑和评论使用同一治理规则；修改文字不能绕过审核或自行恢复人工隐藏状态。审核、管理处置同步更新搜索索引、可见评论数量及待审状态；删除父帖关闭子评论的待审项。模型调整与额度重置均有操作日志。

后台批准用户可使用管理员为其指定的模型，但不能通过自填供应商地址转送共享密钥。测试账号的无限额度不绕过内容治理。

## 本地演示

安装 `requirements.txt` 后运行 `python scripts/local_demo.py`。

脚本固定使用本目录的 `instance/local-demo.db`，忽略生产数据库连接和外部 Redis、搜索、推送设置，只监听本机 `127.0.0.1:5090`。第一次启动生成各自独立的管理员和测试账号、随机密码，并将初始账号资料保存在源码目录外；后续启动不覆盖已有凭据或批准状态。`.env.local`、数据库和本地账号资料不应上传 GitHub 或放入参赛源码包。

本地尚未取得服务器现有 API Key。管理页可保存 DeepSeek 配置，但只有在操作者安全配置有效密钥后才可进行真实模型调用。未配置密钥的演示结果不能当作真实模型测试成绩。

## 模型配置边界

DeepSeek V4.1 Flash 的接口模型标识为 `deepseek-flash`，默认地址为 `https://api.deepseek.com/v1`。依据：[DeepSeek 官方发布说明](https://api-docs.deepseek.com/news/news260910/)。

共享模型使用管理员专用 `/api/admin/model-config`，密钥只返回是否配置，不返回原值。空密钥字段保留已有共享密钥；共享配置持久化时保留数据库等其他设置。普通账号的 `/api/config` 只修改自己的密钥和配置，无个人密钥时不能覆盖共享供应商地址。

运行时设置作用于处理该请求的进程，并写入配置文件。生产若运行多个 worker 或配置由 systemd/容器环境注入，应由服务器所有者同步相应环境并统一重启全部进程后再验证，不能把单进程保存成功视为所有线上进程都已生效。本次没有执行任何重启。

接口地址采用已知供应商 HTTPS 白名单。一个错误个人密钥不会使其他用户转入演示模式。不限应用次数不等于 API 免费或不限流，仍需保留供应商余额、预算、网络限流等限制。
